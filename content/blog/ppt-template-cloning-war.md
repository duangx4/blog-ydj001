> 从 python-pptx 到多模态横评再到模板克隆——一个工科生的 PPT 折腾纪实

---

## 一、背景：为什么一个PPT要搞这么复杂？

事情起源于学院"优秀班集体"评选。

作为班长，要代表班级做答辩汇报
按理说，找个模板，填点内容，完事。但我偏不想将就——既然手头有 AI 工具链，为什么不试试用技术手段做出一个**真正能打**的答辩PPT？

于是，一场延续一整天的"PPT技术路线战争"开始了。

---

## 二、路线1：python-pptx 纯代码生成（❌ 失败）

### 想法
用 python-pptx 库，从零开始用代码生成一整套答辩PPT。全自动化，多酷。

### 实现
- 生成了科技深蓝初版（13页，占位框）
- 优化到 V1 版本（19页，6.3MB）
- 设计了科技感配色 + 几何装饰

### 死因
- 代码只能画占位框和纯色矩形
- **渐变、阴影、SmartArt、动画**——全都要底层 XML 手工写
- 用户评价：**"还不如直接套模板"**

### 结论
python-pptx 适合**修改**现成模板的文字内容，不适合**创造**视觉设计。

---

## 三、路线2：ppt-master 工具链 + AI 生图（⚠️ 部分可行，但不稳定）

### 想法
用之前搭建的 PPT Master 工具链，走完整的三阶段流程：确认 → 选模板 → 生成。

### 实现
- 三阶段 Confirm UI 全部走通
- 生成了两版风格：
  - **蓝金典雅版**（4.5MB）
  - **红金经典版**

### 死因
- AI 生成的封面图质量**忽高忽低**
- 红金经典版用户的原始评价：**"好丑"**

### 结论
生图模型生成的封面风格不稳定，配色可能翻车。适合做**灵感参考**，不能作为最终交付的依赖。

---

## 四、路线3：COM 自动化（❌ 不可用）

### 想法
用 python-pptx + win32com 在 Windows 上直接操作本地 PowerPoint，利用 PowerPoint 的完整渲染能力。

### 死因
- 文件只读错误
- 保存失败
- COM 接口在现代 Office 下的兼容性问题

### 结论
这条路在 Windows 上完全堵死。

---

## 五、路线4：模板克隆 + 内容替换 ✅（最终胜利线）

### 转折点

折腾了大半个上午后，我突然意识到：**为什么要从零开始？手里不是有7套现成的模板吗？**

这些模板来自 [slidesgo.com](https://slidesgo.com) 等平台，每套 30 页左右，设计成熟，配色专业。它们唯一的问题是——内容全是占位符。

### 技术方案

核心思路极其简单：

1. **解压 PPTX**（本质是 ZIP 文件）
2. **删除说明页**（前2-3页的引导页）
3. **用 python-pptx 替换文字内容**
4. **保留所有设计元素**（渐变、阴影、动画、SmartArt）

```python
# 核心代码其实就这几行
import zipfile
from pptx import Presentation
from pptx.util import Inches, Pt

# 解压 -> 删除说明页 -> 重新打包
with zipfile.ZipFile('template.pptx', 'r') as zin:
    # 跳过前2页的说明 slide
    pass

# 替换文字
prs = Presentation('cleaned_template.pptx')
for slide in prs.slides:
    for shape in slide.shapes:
        if shape.has_text_frame:
            for para in shape.text_frame.paragraphs:
                for run in para.runs:
                    run.text = run.text.replace('[班级名]', '22电气X班')
```

### 验证结果

之前已经成功将一个 29 页的蓝底模板克隆成了 36 页的完整答辩PPT，所有设计元素完整保留。

**结论：模板克隆是当前最优技术路线。**

## 六、7套模板的多模态横评

选哪套模板作为底本？我决定用多模态 AI 做一个**量化横评**。

### 对比数据

我提取了7套模板的材质图（每套5张关键页面，共35张），用 DeepSeek V4 模型的视觉能力做评审。

| 🥈 | 红·跟着光 | 35 | 视觉冲击力强，但党建味太重 |

| 7 | 绿·征途漫漫 | 29 | 封面选图与主题不符，致命错误 |

### 为什么要做横评？

因为模板文件太大了——最小的一套 75MB，最大的 125MB。下载一套就要花时间，安装字体还要重启PPT。与其盲猜，不如让 AI 先看素材图，做一轮快速筛选。

### 一个重要教训

**多模态 AI 不能区分"素材图"和"设计成品"。**

一开始我把模板的素材图发给 AI，AI 给出的评分是基于"这是什么设计"的假设，而不是"这是模板的潜力"。后来我加了一句话，效果立竿见影：

> *"以下图片是 PPT 模板的**素材图**，不是最终页面。请评估其**设计潜力**而非当前呈现。"*

### 最终推荐：蓝·博学笃志

- 配色：深海军蓝 `#0B1C45` + 金色金属质感
- 页数：25页最短，最精炼
- 适配：工科电气 + 荣誉感 + 正式答辩，三者完美统一

## 七、实践教训总结

折腾了一整天，踩了无数坑，总结几条有用的：

### ✅ 技术层面上

1. **python-pptx 只适合改内容，不适合做设计。** 渐变/阴影/SmartArt/动画——这些都得靠模板本身。

2. **模板克隆是最优路线。** PPTX 本质是 ZIP，善用这个特性。保留原设计的模板 + 程序化替换文字 = 效率与品质的平衡点。

3. **COM 自动化在 Windows 下不可用。** 别在这条路上浪费时间。

4. **子Agent 的工具集需要预检查。** write 权限、read 目录能力——部署子任务前先列一个工具可用性清单。

### 🧠 方法论层面上

5. **多模态 AI 做设计评审要明确语境。** "素材图"和"成品页面"是两回事，提示词必须区分。

6. **结构数据 + 视觉评估 = 可靠的选型决策。** 单看页数、色号不够，单看素材图也不够，两者结合才有意义。

7. **技术路线失败是正常的，关键是快。** 上午4个小时试了3条路，最终在中午找到了对的方案。快速验证、快速淘汰，比一条路走到黑高效得多。
